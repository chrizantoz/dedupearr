# Changelog

All dates 2026. Image: `ghcr.io/chrizantoz/dedupearr`.

## Unreleased — phase 2, ask the apps; phase 3 begins (2026-11-12)

- New: **Delete all now** on the Actions tab empties the holding bin at once instead of waiting for the days to run out. It asks twice and says plainly that it cannot be undone; a file that changed while it sat in the bin is left alone; every deletion is written in the actions log.
- Fixed (#39): with sign-in on, Auditarr could no longer read the daily summary, so the shared phone message said "no answer this morning". Set `DIGEST_KEY` on the container and the same text as **Dedupearr key** in Auditarr: the key opens `/api/digest` and nothing else, and a key under 16 characters counts as not set.
- Fixed (#34): `CLIENT_PATH_MAP` and `AUDITARR_PATH_MAP` rewrote any path that started with the same letters (`/downloads=…` also changed `/downloads2/…`). They now match whole folder names, like the Plex map.
- Fixed (#37): the Setup tab now shows what Auditarr said on the last scan.
- Housekeeping (#35, #36): the repo no longer carries a link to a folder on a developer's machine, and every test removes its temporary folder when it ends. A lint checks both.

- New, a Plex reader (P2.5): with Plex's address and token set (`PLEX_URL`, `PLEX_TOKEN`, on the container or on the Setup tab), Dedupearr asks Plex each night which folders its film and show libraries look in and which files it has indexed, and names the library files Plex cannot show. Two new verdicts, neither of them waste and neither with a fix button:
  - **Outside Plex's folders**: a library file in a folder no Plex library looks in, so Plex never shows it. It counts under *Needs a decision*, because it is never one file: a whole folder is invisible until you add it to a Plex library, or press Ignore to say it is meant to stay out.
  - **Plex does not show it**: a file inside a Plex folder that Plex has not indexed, usually a name Plex cannot match, a trailer or other extra, or a scan that has not run. This one is a quiet note and does not count under *Needs a decision*: one unmatched name is something to read when you wonder where a film went, not a decision, and counting each would bury the files that do cost space. A file less than a day old is never called this, because Plex may simply not have scanned yet.

  A file that already has a more specific verdict (a real copy with a seeding name, two names for one file) keeps it, and the Plex fact is added to its evidence. Downloads, recycle bins and unsorted folders are never judged by Plex. Music and photo libraries are skipped and named on About. Nothing is ever guessed from half an answer: if Plex is down, refuses the token, or one page of one library fails, no file gets a Plex verdict that night and About says "Plex could not be read" with the reason. The same when none of Plex's folders is a folder Dedupearr can see, which means Plex sees your files under another path: set `PLEX_PATH_MAP`. The token is sent in a header only, and never appears in a log line or on the page. A **Not in Plex** filter appears above the list once Plex is connected. With no Plex address set, nothing changes anywhere. Tests: `tests/plex.py` (54 checks against a pretend Plex), the wounded-answer fuzzer, five mutants, the page bots. The pretend Plex is written from Plex's documented answers, not recorded from a real one, so the first run against a real Plex is the last check before this is relied on.

- Fixed (#33): a **Leftover** that happened to be exactly the size of an unrelated library file named that file as "what the library keeps now" and could be filed under the wrong kind (a TV episode under Movies). The arr's import record now names the library file. Which same-size file was picked also depended on the order the disk lists folders; candidates are now compared in name order.

- Tests (#32): a failed settings check no longer prints a secret setting or a connection with its key; a lint now refuses that in every test.

- New **Setup** tab (P4.1, #13). First the shared-mount test: "Can a library file and a download be one file?", answered from Dedupearr's own mounts and from each arr's import history (an arr that takes downloads from `/downloads` and puts the library in `/tv` copies every import when those are two mounts in its container), with the one-line change when the answer is no. Then one block per arr and download client: address, user, password or API key (never sent back to the page), where it comes from, whether it answered on the last scan, **Save** and **Test** (asks the app with what is saved, reads only). At the bottom, what the arrs list on their Download Clients page.
- New **Settings** tab (P1.7): recycle-bin days, the seeding rule, the smallest file, the scan time, and the folders and folder names that mean library, downloads or recycle bin can be changed on the page; the next scan uses them. A value set on the container always wins and shows locked. Fixes, the folders to scan and the holding-bin days stay container-only. Without a sign-in only your own network may change settings, and a new address forgets the password saved for the old one. Saved in the database in the config folder. Tests: `tests/settings.py` (50 checks), five new mutants, two browser personas.

- New verdict **Extra, not library** (P1.12, quiet part of #12): an opening or ending without credits (NCOP, NCED), a trailer, sample or making-of, a disc image or software in a download folder used to be a *Download without a match*, counted as something to decide. When nothing else is known about it, it is now a quiet row: not waste, not a decision, with one sentence saying what it is. When a client seeds it, it stays **Seeding only** and the sentence now says what it is ("it is an opening or ending without credits"; all 30 such rows on the first real library are extras). An episode whose title merely says *Menu* or *Samples* stays a download to decide on.

- New, three more download clients (P2.3, #15): **rTorrent** (XML-RPC), **Transmission** and **SABnzbd** are read like Deluge, NZBGet and qBittorrent: each row says what the client says, the seeding rule (and each torrent's private flag) decides what can go now, and a failed SABnzbd job nobody imported is a download to decide on, never "seeding". Their answers were recorded from a real rTorrent 0.16, Transmission 4.1 and SABnzbd 5.1 and are replayed by the test stack. The readers only read; a test fails if any other call reaches them. Dedupearr cannot remove torrents from rTorrent or Transmission yet, so their rows say "Remove it in rTorrent first (keep its files)" where the button would be, and no file a torrent still expects is ever moved.
- New, clients found through the arrs (P2.0): with Sonarr or Radarr connected, Dedupearr reads their *Download Clients* page and asks every client listed there, so most people set no client address at all. An address set on the container always wins. The arrs never share passwords or API keys, so a client that needs one says so on About. A client the arrs list as switched off is asked once, briefly: if it still runs its files are explained (they would otherwise look like orphans); if it does not, About notes it quietly instead of calling it broken. A kind Dedupearr cannot read yet is named on About.

- Fix (#30, security): moving a file to the holding bin took the shared lock before checking the file. The lock looks the file up on the disk, so a signed-in request could make Dedupearr look up any path it was sent. The path is now checked against the scanned folders and the scan's own record first; only a file the scan recorded reaches the lock. Nothing could be moved or read this way, and the two refusals read the same as before.
- New, living next to Auditarr (P2.4): with Auditarr's address set (`AUDITARR_URL`), Dedupearr reads the list of files Auditarr changed. A download whose library copy Auditarr edited now says so, with what and when ("Auditarr changed the library copy: it set the default audio and subtitle tracks on 2026-11-13"), where before it could only guess; a download whose library file Auditarr rewrote is a leftover that names Auditarr. Both say the torrent is only still needed for seeding, and neither ever gets a relink offer. About and the morning message say when Auditarr could not be read.
- Fix: files in Auditarr's trash were counted as library files (215 of them on the first real library, and three torrent names were called the seeding name of a "library file" that sat in the trash). They are now **In Auditarr's trash**: not library, not wasted, and never offered for moving or emptying, because Auditarr deletes or restores them itself. The trash is recognised by its folder name, or by Auditarr's own answer when it has another name. Tests: `tests/auditarr_link.py` (26 checks) and three new mutants.
- New, the morning message (P2.6): after the nightly scan Dedupearr can send one message to your phone: how many files need you and how much space can come back, the biggest kinds, what can go right now, what was moved, put back or deleted for good since yesterday, what waits in the holding bin, and any trouble (a failed scan, a download client that could not be read, errors). Set `NTFY_URL` to an [ntfy](https://ntfy.sh) topic to turn it on. The same summary is served at `/api/digest`; Auditarr reads it there and puts both apps in one message, so with Auditarr you set the address in Auditarr and leave `NTFY_URL` empty here. `python dedupearr.py --digest` prints it. Tests: `tests/digest.py` (22 checks, text pinned word for word) and three new mutants.
- New, the lock shared with Auditarr (P3.5, closes #10): the two apps never change one file at the same moment. While a fix works on a file it leaves a small marker in a `.fix-locks` folder at the top of the media share; the other app sees it, leaves that file alone and says why ("Auditarr is working on this file right now (rewrapping the file), so nothing was changed; try again in a few minutes"). The marker is named after the file itself, not its name, so the library name and the seeding name of one file share a lock. A relink locks both files for the whole comparison. A marker older than 6 hours, or one left from before a restart, is ignored. Both apps must see the same folder: set `LOCK_DIR` in both when your folders differ from the defaults.
- New, a whole torrent at once (P3.5, #10): a torrent with several files, such as a season pack, used to be refused. Now its rows offer **Remove torrent, move its N files to holding bin** once every file in it is either a copy the library does not need or a hardlink to the library. The copies go to the holding bin, hardlinks stay where they are, and the client forgets the torrent once and keeps its files. If one file is in no library, or you chose to ignore one, the rows say what to decide first and there is no button. If the client refuses or one file cannot be moved, every file goes back.
- Fix (#26): the page bot hung forever on a file name full of brackets and dashes, which kept an update from going live. The page no longer looks a row up with a selector built from its path; a real browser was never affected.
- New (P3.4, #9): with fixes switched on, a file that has sat in a recycle bin longer than your rule gets **Move to holding bin**, and rides along with **Move all shown**. No fix deletes directly, not even from a recycle bin: the file waits its 14 days in the holding bin and Put back returns it to the bin it came from. Every kind of fix is now switched on.
- New, relink an identical copy (P3.3, #8): with fixes switched on, a download that is a second, identical copy of a library file gets **Make them one file**. Dedupearr compares the two files byte for byte right then (it trusts no checksum from the scan), moves the download copy to the holding bin and puts a hardlink to the library file at its name. A client keeps seeding the same bytes and is told nothing, so this fix does not wait for the seeding rule. If the link cannot be made, for example because the two files sit on different disks of a pool, the copy goes straight back. The comparison runs beside the page with its progress on the row; scans and other fixes wait for it. **Put back** swaps the old copy back in.
- New: **Move all shown to the holding bin**. With fixes switched on and two or more plain moves on the page, one button above the list moves them all, one after the other, each through the same checks as its own button. It follows the filter, the kind and the search box, asks to be sure first, and names any file it left alone. A row that also removes a torrent never rides along, because that cannot be undone; it stays one press on its own row. First part of P3.5 (#10).
- Fix: after a real fix, the page showed "Failed to fetch" when its own refresh failed, although the file had moved. A done fix now says it is done and asks you to reload; a fix that stops with an error answers in words and is kept under Recent errors; every real fix is written to the log (#25).
- New, the first fix that talks to a download client (P3.2, #7): with fixes switched on, a leftover or second copy whose seeding is done gets **Remove torrent, move to holding bin**. Dedupearr asks the client again right before the change, moves the file to the holding bin, then tells Deluge or qBittorrent to forget the torrent and keep its files. If the client refuses, the file goes straight back. A torrent that holds other large files is left alone. **Put back** returns the file for 14 days, not the torrent. Usenet leftovers and files no client knows just move to the holding bin. Nothing changes while `FIX_MODE` is `dryrun` (the default).
- New: a leftover or second copy that is still seeding says where the button would be when it can go ("Still seeding · can go in about 4 days, or sooner at ratio 1"), instead of just having no **Preview fix**. The seeding rule is now `auto` by default: private torrents need the ratio and the days, public ones either (the client's private flag decides) (#23).
- New verdicts **Still downloading** (a client is still downloading it; no more "Seeding only" and torrent words for a usenet job) and **Waiting for import** (finished, and an arr's queue is importing it, or cannot import it on its own; the arr's reason is shown, with where to fix it). Raised by @jonneyblaze in #18 (#20).
- Security: the password set in the container settings is slow-hashed like a page-set one; the holding bin looks up the scan's record before touching the disk (CodeQL, #21). New `alerts` workflow turns each code-scanning alert into an issue every morning.
- Phase 3 starts as a dry run: every fixable row has a **Preview fix** button that shows the exact steps (relink, remove through the client, holding bin, empty an old bin) and the space it would free; `FIX_MODE=dryrun` is the default and nothing is moved, linked or deleted. Every preview is written to the actions log (`/api/actions`). A fix is refused while a scan runs. The real fixes arrive one at a time behind that switch, each with a holding bin and a 14-day undo.

- Download-client and arr readers: Deluge, NZBGet and qBittorrent (seeding state, ratio, time, label, per file) and the arrs' import history (which download became which library file). A download now becomes **Leftover from an upgrade**, **Orphan** or **Seeding only**, each row shows the client's state, and a **can go now** chip appears when your seeding rule (`SEED_MIN_RATIO` and `SEED_MIN_DAYS`, both by default; `SEED_RULE=either` relaxes it) is met or nothing holds the file. Still read-only; the fixes are phase 3.
- Fix: a usenet download that NZBGet finished or failed and no arr imported was called **Seeding only** and counted as 0 B, so a failed job's partial files could hide hundreds of gigabytes (243 GB on one real server). Usenet never seeds: such a file is now a **Download without a match**, counted in full, and its sentence says what NZBGet did with the job. Checks in `tests/clients.py` and `tests/plain_language.py`, and a mutant.
- Sportarr and Lidarr are read like Sonarr and Radarr (`SPORTARR_URL` / `LIDARR_URL` and their keys).
- A client that fails to answer is reported on About and its files fall back to the content-only verdicts; nothing is guessed.
- Download-folder names now include `completed`, `intermediate`, `nzbget`, `sabnzbd` and friends, so usenet folders are not mistaken for the library.

## Phase 1 — scan and tell (2026-11-11)

- First version. Scans the library and download folders, groups names that share one inode, confirms identical copies with checksums, judges recycle bins, and explains every file in one plain sentence with its evidence.
- Files, Space and About pages; nightly scan; Scan now; Ignore.
- New verdict from the first real-library run: "Stored twice, header differs": same size, middle and end identical, only the first megabyte differs, which is a language tag or title edited in place on one copy (Auditarr does this). Relinking such a pair is not safe, and the sentence says so.
- New verdict "Different release in library": a download nothing matches byte for byte, while the library holds another release of the same title (matched on name and year, or name and episode). Almost always a leftover from an upgrade, and the row now says so and names the library file (the Scary Movie case, 2026-11-12).
- Public demo at https://dedupearr-demo.chrizantoz.com (`SANDBOX=1`: the fake disk, per-visitor rate limit, hourly reset) and a project site with a static copy of the page (GitHub Pages).
- Read-only: nothing is moved, linked or deleted.
- Tests: fake disk, verdicts, plain language, API contract, UI bot, data fuzzer, button lint; CI builds and scans the image.
